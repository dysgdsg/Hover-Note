# HoverNote 设计稿 v1

> 这份文档是"写代码之前先想清楚"的产物。它不涉及任何程序改动，目的只有一个：**把每种情况下显示什么字、给什么等级，先定死**，避免边写边改。

---

## 0. 一页看懂

**它是什么**：资源管理器里，鼠标在一个文件或文件夹上停一下，弹出的提示框里多出两行——一句人话解释、一个安全等级。

**它不是什么**：
- 不清理、不删除任何东西
- 不常驻后台，不开托盘
- 不联网，不上传任何信息
- 没有主界面，没有设置窗口
- 没命中任何规则时，就"无痕"——把提示框还给系统原本的样子

**最核心的一句话**：它只提供线索，永远不替你做决定。

## 1. 提示框长什么样

四行纯文本，行与行之间不空行，标签都是两个汉字（对齐好看）：

```
大小   12.3 MB
修改   2025-03-14 10:22
解释   Chrome 的网页缓存，删了会自动重建。
等级   安全 · 可以放心删
```

四档等级，只有这四种写法：

| 等级 | 含义 |
|---|---|
| 安全 · 可以放心删 | 删了通常没事，会自动重建，不含你的个人数据 |
| 谨慎 · 删前先看一眼里面的东西 | 可能是你要用的东西，建议打开看一眼再决定 |
| 危险 · 系统核心，别删 | 系统或软件运行离不开它，删了会出问题 |
| 不确定 · 建议先别动 | 我们不认识它，不猜 |

**不显示的东西**（都是你之前定过的）：
- 不显示完整路径（资源管理器上已经能看到名字了）
- 不显示文件名
- 不加分割线、不加 emoji（提示框是单色的，emoji 只会变成黑白方块）
- 不显示"确认/取消"按钮（不是对话框，就是提示框）

## 2. 判定流水线（按顺序走，先命中先返回）

鼠标停下时，程序按下面的顺序问自己，问到"是"就停下：

```
第 1 步：这是网络位置吗？（\\ 开头 或 网络盘）
         是 → 谨慎 + 专用文案，结束
第 2 步：这是盘符根目录吗？（C:\ 这种）
         是 → 按盘的类型给危险/谨慎，结束
第 3 步：规则表里有没有比它更具体的规则？
         有 → 用最具体那条，结束
第 4 步：它带"从网上下载"的标签吗？
         有 → 解释里加上"从哪下载的"，等级谨慎，结束
第 5 步：它是"用户自己建的地方"吗？（非系统盘、不在已知软件目录）
         是 → 不确定 +"你自己建的文件夹"，结束
第 6 步：都不认识
         → 不确定 · 建议先别动，结束
```

**为什么第 3 步在下载标签前面？** 因为下载的东西如果落在已知位置（比如 `下载` 文件夹），我们仍然先按位置说明它是什么，但"下载标签"信息会**追加**到解释里，两者不冲突：

> 解释   你下载的文件，还放在下载文件夹里。从 github.com 来的。

**为什么要有第 6 步？** 这是"无痕"的保底：不认识的东西绝不硬编一句。界面上仍然是"不确定"，但更彻底的做法是——**如果连一句像样的解释都写不出，就直接返回空，让系统原生的提示框显示**，看起来跟没装一样。

## 3. 规则表怎么设计

### 3.1 每条规则包含什么

| 字段 | 说明 | 例子 |
|---|---|---|
| 编号 | 唯一标识，方便你抽查 | `SYS-SYSTEM32` |
| 匹配式 | 路径长什么样 | `C:\Windows\System32` |
| 匹配方式 | 精确 / 前缀 / 后缀 / 通配 | 前缀 |
| 作用于 | 文件 / 文件夹 / 都算 | 都算 |
| 等级 | 四档之一 | 危险 |
| 解释 | 一句话人话 | 系统的核心文件，删了电脑会坏。 |
| 出处 | 依据来自哪 | 微软文档 / BleachBit 清单 / 经验 |

### 3.2 四种匹配方式

| 方式 | 什么意思 | 例子 |
|---|---|---|
| 精确 | 路径完全一样 | `C:\pagefile.sys` |
| 前缀 | 在这个目录**里面** | `C:\Windows\System32` 命中它下面的所有东西 |
| 后缀 | 按扩展名 | `.tmp` |
| 通配 | 中间有"任意" | `C:\Users\*\Downloads` |

### 3.3 优先级怎么排——"越具体越优先"

这不是靠人排的序号，是**算出来的**：

1. 精确匹配 100 分
2. 前缀匹配：按路径段数算分，**越长越具体，分越高**
3. 通配匹配：通配符越少分越高
4. 后缀匹配：最低（只说明类型，不说明位置）

得分相同时，看人工设的优先级数字。

**举三个例子验证这套规则对不对：**

| 悬停的路径 | 命中的规则 | 结果 |
|---|---|---|
| `C:\Windows\Temp\a.tmp` | `C:\Windows\Temp`（前缀，3 段）比 `C:\Windows`（前缀，2 段）更具体 | 安全 ✓ |
| `C:\Windows\System32\cmd.exe` | `C:\Windows\System32`（3 段）胜出 | 危险 ✓ |
| `D:\我的项目\笔记.docx` | 命中 `.docx` 后缀（谨慎），但"未知位置"不压过它 | 谨慎 ✓ |

### 3.4 路径怎么"归一化"（避免同一路径写成两样）

- 全部转小写再比较
- 去掉末尾的 `\`
- 把 `C:/Users/Alice` 和 `C:\Users\Alice` 视为同一个
- `%USERPROFILE%`、`%LOCALAPPDATA%` 这类变量在运行时展开成真实路径
- 超出 260 字符的长路径，加 `\\?\` 前缀处理

### 3.5 规则表放哪

**放进程序里面（内嵌资源），安装后不额外增加文件。** 仍然是三个文件：
`HoverNote.dll` / `Uninstall.exe` / `README.txt`

开发时的规则源文件可以是一个 JSON（方便你抽查和改），编译时打进 DLL。

## 4. 动态信号（按你上次的追问加的）

静态规则只能覆盖"常见位置"。你真正的问题是"我自己下载的东西，过阵子忘了"。所以加三个**悬停时现场读取**的信号。

### 4.1 下载来源标签（最重要的一个）

浏览器下载文件时，Windows 会给文件贴一个隐藏标签（叫"网络标记"），里面记着来源网址。读它**不联网、不要管理员、只要零点几毫秒**。

读到的内容大致是：

```
[ZoneTransfer]
ZoneId=3
HostUrl=https://github.com/xxx/archive.zip
ReferrerUrl=https://github.com/
```

于是我们可以说：

> 解释   从 github.com 下载的压缩包，2026-03-02 下载。

**降级规则（读不到就跳过，绝不报错、绝不提示"读取失败"）：**
- 不是 NTFS 磁盘 → 没有标签 → 跳过
- 用户右键"解除锁定"了 → 标签没了 → 跳过
- 文件在压缩包里面 → 内层文件没有标签 → 跳过
- 网络盘 → 跳过

**只取域名，不显示完整网址**：
- `https://github.com/xxx/archive.zip` → 显示 `github.com`
- 好处：短、不吓人、不暴露长链接
- 坏处：看不到具体来源页
- 如果你想要完整网址，告诉我，改一行就行

### 4.2 年龄（"多久没动过"）

用创建时间和修改时间算：

**用户已定（2026-10-20）：超过六个月没动过，就加一句时间提示。**

- 6 个月以内 → 不加（最近的东西，不用提醒）
- 超过 6 个月 → 解释末尾加一句"创建于 N 个月前，之后没动过"

**必须诚实的一点**：我们能读到的是"创建时间"和"最后修改时间"，**读不到"你最后一次打开它是什么时候"**。所以文案不能写"六个月没用过"，只能写"六个月前创建，之后没改过"——一个文件夹里你天天看的只读文件，可能也符合这条。若你想更准，得做第 4.3 节的"最近打开"（你已决定不做），那就接受这个精度。

**措辞红线**：只说时间，不说"你大概不需要了"。判断权在你手上。

### 4.3 最近打开过吗（~~二期~~ 用户已决定：不做）

Windows 本地记着"最近用过的文件"。可以读出"上次打开是 3 天前"。

**为什么建议二期**：
- 它只能说明"系统记得打开过"，有些程序打开文件不登记，会出现"从没打开过"但其实天天看的情况——**误导性强**；
- 解析注册表要多写不少代码，测试面变大。

如果你坚持要，我把它做成"可选"，但**默认关闭**。第一版先不加。

## 5. 等级怎么给（这是最容易出错的地方）

原则一句话：**只有"删了会自动重建、且不含你的个人数据"的东西，才敢说"安全"。**

| 判断 | 等级 | 理由 |
|---|---|---|
| 系统核心（Windows、System32、bootmgr…） | 危险 | 删了系统起不来 |
| 软件安装目录（Program Files、ProgramData 里的程序本体） | 危险 | 删了软件坏 |
| 系统级隐藏目录（System Volume Information、Recovery） | 危险 | 删了系统功能坏 |
| 明确的缓存/临时/日志（Temp、Cache、CrashDumps、*.tmp） | 安全 | 会重建、无个人数据 |
| 用户数据（文档、照片、聊天记录、下载、桌面） | 谨慎 | 可能就是你重要的东西 |
| 任何 `.exe` / `.msi` | 谨慎 | 能直接运行，删错就没了 |
| 来历不明、位置陌生的东西 | 不确定 | 不猜 |

**几个特意"往下压"的例子**（宁可保守）：
- `C:\Windows\Installer` → 危险（听着像临时文件，其实是软件安装缓存，删了没法卸载/修复）
- `C:\Users\*\.vscode\extensions` → 谨慎（能重装，但要下几百兆）
- `Downloads` → 谨慎（里面永远有你舍不得删的东西）
- 任何 `.db` / `.sqlite` → 不确定（可能是某个软件的数据库，也可能就是你的数据）

## 6. 文案库（你可以逐条改字）

下面是各场景的"解释"文案，**统一风格：口语、短、不吓人、不说教**。

### 危险类（系统）
| 场景 | 解释 |
|---|---|
| C:\Windows | Windows 系统的老家，删了电脑就起不来了。 |
| System32 / SysWOW64 | 系统的核心文件，动它们电脑会坏。 |
| WinSxS | 系统组件的备份仓库，删了系统更新和修复都会坏。 |
| Installer | 软件的安装备份，删了以后没法卸载或修复软件。 |
| 系统隐藏目录 | 系统自己用的目录，看不出来是干什么的，别动。 |
| 页面/休眠文件 | 系统运行用的临时空间，由系统自己管理，别手动删。 |
| 启动文件 | 电脑开机要用它，删了开不了机。 |

### 谨慎类（你的东西）
| 场景 | 解释 |
|---|---|
| 下载文件夹 | 你下载的东西都堆在这，里面常有舍不得删的。 |
| 桌面 / 文档 / 图片 / 视频 / 音乐 | 这是你自己的东西，删了就找不回来了。 |
| 聊天记录（微信/QQ） | 聊天记录和收到的文件，删了找不回来。 |
| 文档类（docx/pdf/pptx…） | 文档文件，删了就没了。 |
| 图片/视频 | 照片和视频，删了就没了。 |
| 压缩包 | 压缩包，里面装着别的东西，先解压看看是什么。 |
| 安装包（exe/msi） | 软件的安装包，装完了通常可以删，但先确认装好了。 |
| 镜像文件（iso） | 光盘镜像，一般装系统或装软件时才用。 |
| 设计源文件（psd/ai/sketch） | 设计稿的源文件，删了改不了图了。 |
| 用户自己的项目文件夹 | 你自己建的文件夹，HoverNote 不认识里面是什么。 |

### 安全类（垃圾）
| 场景 | 解释 |
|---|---|
| 临时文件夹 | 临时文件，程序关掉后基本没用了，删了会重建。 |
| 浏览器缓存 | 浏览器为了加载快存的东西，删了网页会重新下载。 |
| 缩略图缓存 | 图片的小预览图，删了会重新生成。 |
| 崩溃报告 | 程序崩溃时留下的报告，删了没影响。 |
| 更新下载缓存 | 系统更新的下载残留，装完就没用了。 |
| 日志文件 | 程序运行的记录，删了对使用没影响。 |
| 显卡驱动解压残留 | 驱动安装时解压的临时文件，删了没事。 |
| 下载了一半的文件 | 没下完的残片，删了重新下就行。 |

### 不确定类
| 场景 | 解释 |
|---|---|
| 不认识的东西 | HoverNote 不认识它，建议先别动。 |
| 不认识的文件类型 | 不确定它是什么，打开看看再决定。 |
| 数据库文件 | 某个软件的数据，也可能是你的资料，别乱删。 |
| 配置文件 | 软件的设置，删了软件会恢复默认。 |
| 备份/旧版本 | 看着像备份或旧版本，确认没用了再删。 |
| 被占用 | 有程序正在用它，先关掉那个程序。 |

## 7. 兜底与降级（"稳"字的具体体现）

程序必须做到：**任何一步出问题，都不能影响你正常用电脑。**

| 可能出问题的地方 | 后果如果不管 | 我们的处理 |
|---|---|---|
| 规则表读不出来 | 提示框空白 | 直接返回空，系统原生提示照常显示 |
| 读下载标签失败 | 报错框 | 静默跳过，只少一句来源 |
| 文件正被占用 | 卡住 | 只读不锁，读不到就算了 |
| 路径特别长 | 抛异常 | 加长路径前缀再试，失败就跳过 |
| 网络盘没连上 | 卡顿 | 3 秒内没响应就当"不知道"，绝不等待 |
| 程序本身崩了 | 资源管理器跟着卡 | 所有代码包在 try/catch 里，异常一律"返回空" |

**最重要的一条**：资源管理器是单线程等我们的。我们**必须快**，宁可说"不知道"，也不能让它卡住。

## 8. 边界情况清单（我会逐条测）

| 情况 | 期望表现 |
|---|---|
| 盘符根 `C:\` `D:\` | 显示"这是整个磁盘"，按盘类型给等级 |
| 网络位置 `\\NAS\share` | 谨慎 + "网络位置，速度慢" |
| 映射的网络盘 `Z:\` | 同上（靠"网络盘"判断，不能只看开头是不是 \\） |
| 压缩包里的文件 | 说明"在压缩包里"，不给删的建议 |
| 回收站里的文件 | "已经删了，在回收站里" |
| 隐藏文件 | 照常显示，不特殊对待 |
| 没有扩展名的文件 | 不确定 |
| 管理员权限打开的资源管理器 | 提示可能不显示（注册表作用域不同），README 说明 |
| 刚下载还没下完的文件（.crdownload/.part） | 安全，说明是没下完的残片 |
| 移动硬盘 / U 盘里的文件 | 按路径和类型判断，不假设是系统盘 |

## 9. 性能与隐私

**性能预算**（每次悬停总耗时）：
- 读规则 + 路径匹配：< 1 毫秒
- 读下载标签：< 1 毫秒
- 读文件时间：< 1 毫秒
- 合计目标：**5 毫秒以内**（你几乎感觉不到）

**隐私承诺**：
- 全程只读本地信息，**不联网**
- 不写任何日志文件（正式版会删掉现在调试用的日志代码）
- 不记录你悬停过什么
- 不采集任何统计

## 10. 安装和卸载会动你电脑的哪里

**只动这些，别的一概不碰：**

| 位置 | 干什么 |
|---|---|
| 你选的安装目录 | 放三个文件 |
| `HKCU\Software\HoverNote` | 记录装在哪，方便卸载 |
| `HKCU\Software\Classes\CLSID\{...}` | 告诉系统"这个扩展在哪" |
| `HKCU\Software\Classes\*\shellex\...` | 挂到"所有文件"上 |
| `HKCU\Software\Classes\Directory\shellex\...` | 挂到"所有文件夹"上 |
| `HKCU\Software\Classes\Drive\shellex\...` | 挂到"磁盘"上 |

- 全部在 `HKCU`（当前用户）下，**不需要管理员权限**
- 不碰 `HKLM`、不碰系统目录、不装服务、不设开机启动
- 卸载 = 删掉上面几个注册表项 + 删掉三个文件，电脑恢复原样

## 13. 开源与"能被人接手"

用户原话：**"我希望我开源后，会有人能接过我，做的更好"**。所以交付标准不只是"能跑"，而是"陌生人拿到能看懂、能改、能发版"。

### 13.1 仓库里应该有什么

| 文件 | 作用 |
|---|---|
| `README.md` | 这是什么、怎么装、怎么卸、支持什么系统；图文并茂，第一屏就能看懂 |
| `LICENSE` | MIT，全文 |
| `docs/DESIGN.md` | 本文件——决策和取舍都在这里，接手的人不用猜 |

### 13.2 交接友好的几个硬要求

1. **零依赖构建**：只用 Windows 自带的编译器（`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`），新人 `git clone` 后跑一个脚本就能编译。
2. **规则与代码分离**：加规则只改 JSON，不碰 C#；降低"想帮忙但不会 C#"的门槛。
3. **每个关键决策留下"为什么"**：比如为什么不用 SharpShell、为什么 InprocServer32 要写 mscoree.dll —— 否则接手的人会"好心"改回去，然后踩同一个坑。
4. **测试用例可复制**：`TestHarness.exe` 能对任意路径打印判定结果，方便对比改前改后。
5. **README 写明已知限制**（管理员窗口不显示、压缩包内文件、网络盘），减少接手人被 issue 淹没。
